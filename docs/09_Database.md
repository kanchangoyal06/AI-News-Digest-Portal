# Database Documentation

The application uses MongoDB (via Mongoose ODM) to structure and persist data. 

## 1. User Model (`models/User.js`)
- **Purpose**: Stores authentication credentials and role flags.
- **Fields**:
  - `name` (String)
  - `email` (String, Unique)
  - `password` (String)
  - `isAdmin` (Boolean, default: false)
- **Lifecycle Hooks**:
  - `pre('save')`: Hashes the password using `bcryptjs` before inserting into the database if the password field was modified.
- **Methods**:
  - `matchPassword(enteredPassword)`: Compares the plain-text password with the stored bcrypt hash.

## 2. Article Model (`models/Article.js`)
- **Purpose**: Stores curated news articles verified by Gemini.
- **Fields**:
  - `title` (String, Required)
  - `url` (String, Required, Unique): Prevents duplicate scraping.
  - `source` (String)
  - `publishedAt` (Date)
  - `summary` (String): The 3-sentence summary generated by Gemini.
  - `importanceScore` (Number): Graded by Gemini (1-10).
  - `status` (String): `['Pending', 'Sent', 'Rejected']`
- **Indexes**:
  - `{ status: 1, publishedAt: -1 }`: Optimizes the query used in the Dashboard to group and filter articles efficiently.

## 3. Digest Model (`models/Digest.js`)
- **Purpose**: An audit log of generated `.eml` files.
- **Fields**:
  - `sentBy` (ObjectId, ref: 'User')
  - `articles` ([ObjectId], ref: 'Article')
  - `status` (String): `['Success', 'Failed', 'Downloaded']`
- **Relationships**: A Digest contains many Articles.

## 4. Settings Model (`models/Settings.js`)
- **Purpose**: A strict singleton document storing global application configurations.
- **Fields**:
  - `defaultPrompt` (String): The exact prompt sent to Gemini AI.
  - `receiverEmails` ([String]): Array of target emails injected into the `.eml` draft.
- **Lifecycle**: Seeded automatically at server startup if it doesn't exist. There will only ever be a single document in this collection.
